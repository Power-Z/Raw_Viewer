# V0.7.14 全图统计与 Display Window 性能优化

## 1. 问题定位

V0.7.13 功能口径正确，但交互卡顿由三条独立链路叠加造成：

1. 直方图双手柄每次 `mouseMove` 都提交 Display Mapping，触发视口 LUT、可见图像缓存和预览重绘；
2. 直方图每次重绘都重新把最多四路 65,536 bins 聚合到屏幕列，即使数据和横轴区间均未变化；
3. 完整 Grayscale16/RGBA 已存在连续内存时，全图统计仍逐像素调用虚接口 `IPixelSource::sample`。

## 2. 优化方案

### 2.1 BLV/WLV 提交策略

- 双手柄拖动期间只更新控件内部值和右侧一位小数输入，不修改 `DocumentSession`，不重建 RAW 显示缓存；
- 松开鼠标后一次性执行 Display Mapping、视口刷新和历史提交，完整拖动仍只占一个 Undo 步骤；
- SpinBox 关闭 keyboard tracking，BLV/WLV/Gamma 采用 120 ms 单次防抖；停止输入或失焦时应用，连续输入不会逐键重算；
- Undo 执行前会先封存仍在等待防抖的输入，避免延迟任务覆盖撤回结果。

### 2.2 全图扫描快速路径

- 当 `DisplayImage` 包含与源尺寸一致的 Grayscale16 连续视图时，直接按 stride 扫描 `uint16_t`；规则 Bayer 使用预计算的 2×2 parity→series 表分流；
- UInt16 + 65,536 bins 直接以码值作为 bin 索引，省去每像素浮点归一化；
- 当完整 RGBA 预览与源尺寸一致时直接顺序读取 R/G/B，并计算 Y；
- Filter、Transform、Extract 等惰性/重排源继续走 `IPixelSource` 通用路径，保持精确语义；
- 所有路径仍按约 4,096 样本检查 cancellation，旧文档结果不会覆盖新源。

### 2.3 绘制与 RAW 映射缓存

- 65,536-bin→屏幕列的聚合结果按 `result + view range + widget width` 缓存；拖动手柄只重绘标记和遮罩，不再扫描 bins；
- Grayscale16 的 65,536 项 LUT 改为一次验证后直接计算；Gamma=1 时走线性分支，不执行 65,536 次 `pow`；
- 可见 RAW 映射缓存仍限定为屏幕可见矩形，不创建第二份完整图像。

## 3. 显示语义

RAW 默认 Gamma 改为 1.0：

```text
value <= BLV  -> 0（全黑）
value >= WLV  -> 1（全白）
中间值         -> (value - BLV) / (WLV - BLV)
```

Gamma 非 1 时继续在归一化结果上执行 `pow(normalized, 1/gamma)`。完整 Grayscale16 RAW 的 Display 控件保持可用，SpinBox 与直方图双手柄双向同步。

## 4. 验证

- 默认 Gamma=1 及 BLV/WLV 以下、区间中点、WLV 以上的映射黄金值；
- 完整 Grayscale16 全图统计保持 `IPixelSource::sampleCalls == 0`，证明使用连续内存快速路径；
- 直方图第一次绘制建立一次投影，连续拖动后 projection build count 不增加；
- 主窗口连续 12 次拖动事件期间 Undo 保持禁用，松手后才启用，SpinBox 与手柄值一致；
- 32768 信号在 `[0,65535]`、`[0,32768]`、`[32768,65535]` 下分别显示中灰、全白、全黑。
