# V0.7 RAW 像素值标注优化

## 需求与实现

| ID | 需求 | 实现与验收 |
|---|---|---|
| V0.7-01 | RAW 像素标注不显示 `Raw` 前缀 | Flat RAW 和 Camera RAW 的原始信号标签只格式化数值；普通 RGB 图片的既有信息格式不在本次范围内。 |
| V0.7-02 | 字体只使用黑白两色并随背景调整 | 按当前显示预览中对应像素的亮度选择颜色：亮度不低于 140 使用黑字，否则使用白字；删除半透明标签底板和彩色 Bayer 字体。 |
| V0.7-03 | 默认不绘制像素边界线 | `PixelOverlayOptions::showMesh` 与 Pixel Info 对话框的 `Bayer mesh` 默认值改为关闭；用户仍可手动开启。 |
| V0.7-04 | 字高约为显示像素高度的 1/7 | 每帧按 `round(zoom / 7)` 设置字体 pixel size；文字使用自然宽度并以像素中心对齐，位数越多宽度越大。 |
| V0.7-05 | 优化标注后的拖拽和缩放流畅度 | 拖拽期间不查询或绘制标注；滚轮连续缩放期间暂停标注，最后一次滚轮事件 80 ms 后恢复；控件声明为 opaque，避免系统重复清空背景。 |

## 卡顿原因分析

原实现每次鼠标移动或滚轮事件都会触发完整视口重绘。启用标注后，每一帧还会：

1. 查询最多 200 个原始像素并计算 Display、RGB 和 Bayer 信息；
2. 为每个标签创建字符串列表、计算换行边界并绘制半透明背景；
3. 默认绘制当前可见区域的全部横向和纵向网格线。

拖拽和连续滚轮缩放时，中间帧会迅速失效，但上述工作仍会重复执行，因此交互负担主要来自短生命周期标注层，而不是 RAW 数据顺序或提取算法。

## 优化策略

- 图像底层在交互过程中继续实时重绘，保证位置和缩放反馈连续。
- 标注层在拖拽按下到释放之间暂停；滚轮使用 80 ms 单次定时器合并连续事件。
- 恢复标注后仍只扫描可见像素，并继续遵守 200 个默认标签上限。
- 删除默认网格、标签背景矩形、Flat RAW 的多字段拼装和不必要的文本边界计算。
- 不缓存整幅 RAW 或生成额外全图副本。

## 自动化验证

`PixelStatisticsUiTest::rendersReadableRawPixelValuesAndSuspendsDuringPan` 使用 2×1 黑白 UInt16 RAW 离屏渲染，验证：

- 黑色像素显示白字，白色像素显示黑字，画面内部只出现灰度颜色；
- 单值 `0` 的文字宽度排除旧 `Raw 0` 前缀，字高符合约 1/7 比例；
- 默认 mesh 关闭；
- 拖拽和滚轮缩放中标签消失且原始像素查询次数不增加；
- 释放拖拽或停止滚轮 80 ms 后标签与像素查询恢复。
