# V0.7.5 提取结果像素标注修复

## 排查结论

V0.7.5 的异常不来自多次 Bayer Extract 串接。`MainWindow::beginBayerExtraction` 每次都把 `DocumentSession::original()` 作为请求源；连续执行 R、Gr 两次 2×2 提取时，第二次输出仍为原图 Gr 位置的 `1、3、21、23`，没有在第一次 R 结果上继续提取。

问题位于像素标注的 Bayer 通道判定。非恒等提取会把选中位置紧凑排列，输出不再具有规则的二维 Bayer 周期，因此结果元数据按设计把 `bayerPattern` 设为 `None`。此前 `ImageViewport` 只根据该元数据计算 R/Gr/Gb/B，导致提取后的数值像素源虽然正确，Bayer mesh 和 pattern 标注却丢失。

## 实现

| 需求 ID | 行为 | 实现与约束 |
| --- | --- | --- |
| V0.7.5-01 | 像素值始终读取当前显示 RAW | 主窗口继续以 `displaySource_` 渲染；提取完成时切换到新的只读 `BayerPlanePixelSource`，视口换图会使旧标注缓存失效。 |
| V0.7.5-02 | 连续 Extract 不得链式改变输入 | 保持 V0.6 契约：每次请求都以 `original()` 为源，并用 generation/cancellation 防止旧任务覆盖新结果。 |
| V0.7.5-03 | 紧凑提取后仍能正确标注 Bayer 通道 | `IPixelSource` 增加默认无通道的坐标查询；`BayerPlanePixelSource` 将输出坐标映射回原图，并返回原图位置的 Bayer 通道。`queryPixelInfo` 与 `ImageViewport` 优先使用该溯源信息，再回退到规则元数据。 |

该改动不复制像素数据，也不把整幅通道展开到内存；通道查询只做已有几何映射，不读取 RAW 样本。Pixel Statistics 的四通道开关仍以规则输出元数据为准，因此没有擅自改变 V0.7.4 对无规则紧凑图的统计口径。

## 验证

- `DocumentSessionTest::keepsPixelInfoOnLatestIndependentExtraction`：连续以同一 original 执行 R、Gr 提取，验证第二次精确值 `1、3、21、23`，并验证 Pixel Info 返回 `Gr`；
- `PixelStatisticsUiTest::rendersExtractedPixelAnnotationsFromSourceCoordinates`：验证提取结果元数据为 `None` 时，当前视口仍绘制来自原图坐标的 Gr mesh/pattern 和像素数值，重复重绘不重复读取像素；
- `PixelStatisticsUiTest::pixelAnnotationUsesSecondIndependentExtraction`：主窗口端到端先提取 R、再提取 Gr，验证第二次输出 `(0,0)` 显示 `Source (1, 0) | Raw 1`；若错误地链式提取，该值会是 `Raw 2`；
- Windows MSVC Debug/Release 构建通过，Debug/Release CTest 均为 4/4。
