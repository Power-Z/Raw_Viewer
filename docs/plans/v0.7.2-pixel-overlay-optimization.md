# V0.7.2 像素标注启动与性能优化

## 需求与实现

| ID | 需求 | 实现与验收 |
|---|---|---|
| V0.7.2-01 | 未打开 Pixel Info 时，放大到阈值也应自动显示像素标注 | 主窗口创建视口后立即同步 `PixelInfoDialog::options()`；离屏 UI 测试在未触发 Pixel Info 操作的情况下验证首次渲染已读取并显示像素值。 |
| V0.7.2-02 | Bayer pattern 的 R/Gr/Gb/B 字体使用不同颜色，Gr/Gb 必须可区分 | Pattern 字体按通道使用红、亮绿、青绿、蓝四套颜色，并根据明暗背景选择深色或亮色变体；2×2 RGGB 离屏渲染分别验证四个标签区域的颜色特征。 |
| V0.7.2-03 | 减少像素标注从无到有以及连续交互时的卡顿 | `ImageViewport` 缓存当前可见区域及两像素边界内的通道、背景亮度、格式化数值和静态文本布局；拖拽、缩放或重复重绘复用重叠单元，仅对新进入缓存区域的坐标调用 `IPixelSource::sample`。缓存随图像、显示映射或数值开关变化失效，容量始终受当前视口约束。 |

## 性能策略

- 缓存仅覆盖可见区域附近，不扫描完整 RAW，也不建立整图标签索引；
- 像素值使用 `QStaticText` 的 aggressive caching，避免每帧重复文字排版；
- mesh、数值和 Pattern 分层绘制，按有限颜色分组，减少频繁切换字体和画笔状态；
- 保留 V0.7.1 的连续逐帧显示语义，不恢复拖拽/滚轮期间隐藏标注的策略；
- 达到 40 px/像素阈值后仍标注全部可见像素，不进行抽样或跳点。

## 自动化验证

- `enablesPixelOverlayBeforePixelInfoIsOpened`：确认主窗口初始状态已经启用默认像素标注；
- `rendersContinuousCompletePixelValues`：确认平移、缩放和重复渲染持续显示标注，同时已缓存像素不发生重复采样；
- `rendersBayerMaskAndPatternLabels`：确认四色 mesh 保持不变，Pattern 字体分别呈现 R/Gr/Gb/B 独立颜色；
- Debug/Release 全套 CTest 用于回归 RAW 解码、统计、Bayer Extract 与 Recent Files。
