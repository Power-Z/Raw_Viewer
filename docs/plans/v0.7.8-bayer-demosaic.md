# V0.7.8 Bayer Demosaic 调研、可行性与实施方案

## 1. 需求与边界

| ID | 验收口径 |
|---|---|
| V0.7.8-01 | Tool 菜单和右侧工具区增加 Demosaic，并提供专业紧凑子窗口。 |
| V0.7.8-02 | 提供三种常用方法：Bilinear、Malvar–He–Cutler、Hamilton–Adams。 |
| V0.7.8-03 | 输入为当前显示的规则 Bayer RAW；支持 RGGB、BGGR、GRBG、GBRG，不对 Standard RGB 或重排后 `BayerPattern::None` 的图像错误处理。 |

Bayer CFA 的基础排列来自 Bryce Bayer 的 [Color imaging array, US 3,971,065](https://patents.google.com/patent/US3971065A/en)。Demosaic 的目标是在每个只有一个实测颜色的位置估计另外两个颜色，从单通道 CFA 恢复完整 RGB。

## 2. 算法调研

### 2.1 Bilinear

双线性插值是最低成本基线：R/B 位置的 G 使用十字邻域平均，对向颜色使用四个对角邻域平均；G 位置按 CFA 方向分别水平或垂直插值 R/B。

- 邻域半径：1；
- 复杂度：O(W×H)，常数最小；
- 优点：简单、稳定、适合快速预览和算法对照；
- 局限：高对比边缘容易产生 zipper、伪色和细节模糊。

OpenCV 的官方颜色转换文档仍将 bilinear、VNG 和 Edge-Aware 作为 Bayer demosaic 的典型类别并列：[OpenCV Color Space Conversions](https://docs.opencv.org/4.12.0/d8/d01/group__imgproc__color__conversions.html)。

### 2.2 Malvar–He–Cutler（MHC）

MHC 使用固定 5×5 线性滤波器，在双线性结果上利用通道间高频相关性做 Laplacian 修正。原论文 [High-quality linear interpolation for demosaicing of Bayer-patterned color images](https://www.microsoft.com/en-us/research/publication/high-quality-linear-interpolation-for-demosaicing-of-bayer-patterned-color-images/) 报告相对 bilinear 的 PSNR 提升可超过 5.5 dB，同时保持较低线性计算复杂度。IPOL 的独立算法说明和公式见 [Malvar–He–Cutler Linear Image Demosaicking](https://www.ipol.im/pub/art/2011/g_mhcd/)。

- 邻域半径：2；
- 复杂度：O(W×H)，每个缺失通道为固定 5×5 sparse kernel；
- 优点：质量/成本比好、无方向分支、结果可复现，适合作为默认方法；
- 局限：不是内容自适应方法，在极强边缘和周期纹理处仍可能出现伪色；线性修正可能超出输入范围，显示映射阶段需要 clamp。

### 2.3 Hamilton–Adams Edge-Aware（HA）

Hamilton–Adams 先比较水平/垂直的一阶绿色梯度和同色二阶差分，在较平滑方向恢复 G，再通过 R−G/B−G 色差恢复另外两个通道。原始方向分类和插值设计见 [Adaptive color plane interpolation, US 5,652,621](https://patents.google.com/patent/US5652621A/en)。

- 有效邻域半径：3（第二阶段色差需要访问已估计 G 的邻域）；
- 复杂度：O(W×H)，但分支和绝对值运算多于 MHC；
- 优点：能顺着水平/垂直边缘插值，通常减少 zipper 和跨边缘混色；
- 局限：方向判定在噪声或细密周期纹理中可能不稳定，计算成本高于 bilinear/MHC。

### 2.4 本轮未选择的方法

| 方法 | 特点 | 暂不进入前三项的原因 |
|---|---|---|
| VNG | 根据多个梯度选择参与插值的方向；OpenCV 提供官方实现入口 | 梯度数量、分支和邻域更大，CPU 惰性瓦片首像素延迟高；与 HA 的产品定位重叠。 |
| AHD | 在多个候选方向之间用颜色同质性决策 | 需要更大的中间 RGB/Lab 状态与候选缓冲，不适合当前无整图副本阶段。 |
| DCB/迭代法 | 多轮颜色差修正，细节质量较高 | 多次邻域迭代放大瓦片 halo 和缓存依赖，第一版难以保证交互延迟。 |
| 学习型方法 | 可在特定数据集上达到更高指标 | 引入模型、推理运行时、训练域偏差和 GPU/内存要求，不符合当前 C++20 CPU 基线。 |

选择 Bilinear/MHC/HA 可以形成清晰的速度—质量梯度，同时三者都只依赖有限局部邻域，适合现有 `IPixelSource` 惰性接口。

## 3. 数据与颜色口径

- Demosaic 捕获 Apply 时的 `displaySource_`。Filter 保留规则 Bayer 元数据，因此 Filter → Demosaic 有效；非恒等 Bayer Extract 将排列设为 None，Demosaic 必须禁用。
- 插值在当前显示 RAW 的标量域完成，实测 CFA 通道值原样保留；边缘使用 reflect 边界。
- RGB 输出使用 Apply 时的 Display BLV/WLV/Gamma 映射为 8-bit display-ready RGB，避免输出再次经过 RAW 范围映射。
- Demosaic 结果是终端 Standard RGB 显示源；Filter、Pixel Statistics 和再次 Demosaic 禁用。`Show Bayer Source` 恢复此次 Demosaic 的输入，可更换算法重试。
- 当前版本未执行相机色彩矩阵、白平衡、色域转换或 tone mapping；输出是 CFA 插值结果，不等同于完整相机 ISP 成片。

## 4. 性能设计

### 4.1 有界预览

后台任务计算最长边 1024 的 RGB 预览，不构造 W×H RGB。原始解码源在对应源坐标读取算法所需局部邻域；Filter 输出额外携带保持 2×2 CFA phase 的有界 signal preview，Demosaic 直接在该内存预览上运行，避免对惰性 Filter 源进行稀疏查询时意外触发大量准确瓦片。Filter → Demosaic 的预览阶段对底层原始像素零新增读取。过期或取消任务每行检查 token。

### 4.2 准确像素瓦片

`DemosaicedPixelSource` 按需生成 64×64 RGB 瓦片。每块统一读取 3 px halo，即最大 70×70 个源样本；三种算法都在内存邻域上完成，避免每个输出像素重复访问底层映射文件。LRU 最多 320 块，约 5 MiB，可保留约 20K 宽图像的一整条瓦片行，避免逐行 Pixel Info/后续读取发生缓存抖动。

对 128×64 输出，两块准确瓦片只读取 `2 × 70 × 70 = 9,800` 个源样本；第二次遍历零新增读取。相比 MHC 每像素直接读取 25 次的 204,800 次，底层读取减少约 95%。

## 5. 子窗口 UI

窗口固定约 410 px 宽，由两个直角技术面板组成：

1. `DEMOSAIC ALGORITHM`：单一下拉框和随方法变化的 FAST / RECOMMENDED / EDGE-AWARE 说明；
2. `CURRENT BAYER PIPELINE`：当前尺寸、Bayer pattern、格式和执行状态；
3. 底部显示 1024 preview / lazy tiled exact RGB 性能说明；
4. `Show Bayer Source`、`Close`、`Apply` 操作区。

默认选择 MHC。输入不是规则 Bayer RAW 时，Apply 禁用并明确显示原因。

## 6. 验证计划

- RGGB/BGGR/GRBG/GBRG × Bilinear/MHC/HA 的常量颜色黄金值；
- 单点脉冲黄金值分别验证 bilinear、MHC 5×5 系数和 HA 方向/色差路径；
- 1024 预览边界、9,800 次双瓦片读取、重复访问零读取；
- None pattern 与预取消结构化错误；
- UI 默认算法、三种说明、紧凑尺寸和不可用状态；
- 主窗口 Mean Filter → Bilinear Demosaic 的角点 RGB `37,51,61`，证明输入来自当前显示滤波结果；恢复后 Demosaic 工具重新启用。
