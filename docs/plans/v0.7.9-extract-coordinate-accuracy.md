# V0.7.9 Extract 坐标与显示一致性方案

## 1. 需求

- RAW 显示区只保留顶部 X 标尺和左侧 Y 标尺，颜色跟随当前主题；
- Bayer Extract 的显示像素、输出尺寸和界面坐标必须属于同一个紧凑输出坐标空间；
- 200×200 输入按 2×2 仅保留左上位置时，结果必须为 100×100，界面不得用原图坐标替代当前坐标。

## 2. 排查结论

Extract 领域映射没有执行多次提取：`MainWindow` 每次都把 `DocumentSession::original()` 传给 `BayerExtractService`。单位置提取的几何也正确，输出 `(x,y)` 映射到源 `(2x,2y)`，因此 200×200 输入得到 100×100 输出。

实际问题有两层：

1. 状态栏同时显示 `Extract (output) → Source (original)`，把当前紧凑坐标和原图坐标混在一个主要界面中，用户无法把标尺、像素格和左下角坐标当作同一坐标空间；
2. 大图非恒等 Extract 只生成最长边 1024 的信号预览。视口放大该预览时，背景灰度来自降采样像素，而数值标注直接查询精确 `IPixelSource`，所以同一个输出坐标可能出现背景与标注值不一致。

## 3. 实现

### 3.1 当前输出坐标

- `DecodedImage::metadata.width/height`、`IPixelSource::width/height`、标尺和鼠标命中都继续使用 Extract 输出尺寸；
- 状态栏对 Extract 只显示当前 `(x,y)`、Raw、Display 和通道，不再展示原图坐标；
- 源坐标映射仍保留在 `BayerPlaneGeometry` 内部，供算法、通道溯源和测试使用，不暴露为默认浏览坐标。

### 3.2 精确像素层

- 低倍率继续绘制最长边 1024 的有界预览，避免扫描数亿像素；
- 当缩放达到 16 px/像素且预览尺寸小于输出尺寸时，仅查询当前可见输出区域；该阈值下 4K 画布通常只需约 32K 样本；
- 精确层缓存增加 2 像素边缘，最多 65,536 个样本；相同图像、DisplayMapping 和包含区域的重复重绘不再查询像素源；
- 标量 RAW 使用当前 DisplayMapping 转为灰度，RGB 输出直接使用精确 RGB 样本；无效补位显示为黑色。

### 3.3 标尺

- 画布为左侧 24 px Y 标尺、顶部 24 px X 标尺、底部/右侧滚动条；
- 标尺背景、边框和文字分别使用 `QPalette::Window`、`Mid`、`WindowText`；
- X/Y 使用同一图像变换和 nice-step 算法，刻度严格落在当前输出像素边界。

## 4. 验证

- 应用层：200×200、2×2 左上单点得到 100×100；输出 `(99,99)` 的值和源 `(198,198)` 一致；
- UI：Extract 状态栏包含当前 `坐标 0, 0`，不包含 `Source`；
- UI：人为构造 1×1 黑色缩略预览和 2×1 黑/白精确源，高倍率渲染仍分别显示黑/白，第二次重绘查询次数不增长；
- UI：自定义主题色下顶部和左侧刻度均与输出像素 5 的边界对齐。
