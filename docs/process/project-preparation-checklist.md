# 项目准备清单

这份清单用于 V0.0 到 V0.1 的交接。未确认的项目可以暂记为“待定”，但涉及公开发布、数据授权和密钥安全的项目必须在执行前确认。

## A. GitHub 与权限

- [ ] 确定 GitHub 仓库所有者（个人账号或组织）。
- [ ] 确定仓库名称和可见性；初期涉及内部 RAW 数据时优先使用私有仓库。
- [ ] 所有维护者启用双因素认证，并至少准备两种恢复方式。
- [ ] 配置本机真实 Git 提交姓名和 GitHub noreply 邮箱。
- [ ] 选择 HTTPS 凭据管理器或 SSH key，不在文档和仓库中保存令牌。
- [ ] 设置 `main` 分支保护、必要检查和合并策略。
- [ ] 明确谁可以审查、合并、发布和修改仓库设置。

## B. 法务、知识产权与数据

- [ ] 确认项目代码、算法和界面素材的所有权。
- [ ] 在公开仓库前选择许可证；未选择许可证不等于允许他人自由使用。
- [ ] 建立第三方依赖许可证审查流程。
- [ ] 对每份 RAW 样本记录来源、授权范围、敏感性和保留期限。
- [ ] 准备小型、脱敏、可再分发的测试样本；大型或受限样本放在受控存储。
- [ ] 为外部样本保存 SHA-256 校验和，保证测试可复现。

## C. 产品与技术输入

- [ ] 完成业务与数据需求文档中的 P0 内容。
- [ ] 明确首发操作系统、最低硬件与是否允许联网。
- [ ] 明确首发支持的 RAW 位深、打包方式、Bayer 排列和元数据来源。
- [ ] 为关键算法准备可信参考输出和允许误差。
- [ ] 明确性能基准设备、数据规模和可测量目标。
- [ ] 用技术验证原型排除最危险的假设，再确定 GUI 与算法技术栈。
- [ ] 通过 ADR 记录重要技术取舍。

## D. 工程质量

- [ ] 确定代码格式、静态检查、单元测试和覆盖率策略。
- [ ] 为 RAW 解析准备边界、损坏、截断和大文件测试。
- [ ] 为算法准备黄金样本、数值误差和跨平台一致性测试。
- [ ] CI 至少执行构建、测试、静态检查和依赖安全检查。
- [ ] 约定日志级别、隐私脱敏、崩溃转储和问题诊断包格式。
- [ ] 测试取消操作、内存不足、文件不可访问等故障路径。

## E. 发布与运维

- [ ] 确定版本号、变更日志和发布审批规则。
- [ ] 确定安装包格式、代码签名证书和自动更新策略。
- [ ] 构建可从干净环境复现，发布产物生成校验和。
- [ ] 明确支持渠道、缺陷优先级和安全问题报告方式。
- [ ] 建立源码、制品和测试数据备份，并实际演练恢复。
- [ ] 定期检查依赖更新、过期凭据、仓库权限和无人维护风险。

## 建议的确认顺序

1. 仓库所有权、私有/公开与数据授权；
2. 业务场景和 RAW 数据定义；
3. 性能目标和验收样本；
4. 架构与技术验证；
5. MVP 开发、测试和持续集成；
6. 签名、发布、支持与备份恢复。
