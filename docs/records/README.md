# 长期维护记录

本目录保存“当前事实和持续变化的记录”。稳定的技术理由放在 `docs/decisions/`，未来工作拆分放在 `docs/plans/`。

| 文件 | 用途 | 更新时机 |
|---|---|---|
| `project-status.md` | 当前版本、完成项、下一步和阻塞 | 每个合并或里程碑 |
| `requirements-traceability.md` | 需求到设计、实现、测试的映射 | 需求或验收变化 |
| `risk-register.md` | 技术、数据、许可和进度风险 | 发现风险及每月复审 |
| `test-data-manifest.md` | 样本来源、参数、授权和校验和 | 新增/替换样本 |
| `technical-debt.md` | 已接受的工程欠账及偿还条件 | 引入或关闭债务 |
| `release-checklist.md` | 构建、测试、许可、制品和恢复检查 | 每次发布 |

维护规则：

- 记录应包含日期、责任人和可验证证据；
- 不删除已发生记录，关闭项保留状态和关闭原因；
- 不在记录中粘贴访问令牌、客户数据或完整敏感路径；
- Issue 可以承载讨论，但最终结论必须回写仓库；
- 记录与代码不一致时，视为未完成。
