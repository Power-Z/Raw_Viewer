# 架构设计入口

## 当前状态

V0.0 尚未完成业务、数据、性能和部署环境确认，因此本目录只记录约束和设计流程，不做具体框架选型。

## 已确认约束

- 软件面向 Bayer RAW 图像浏览、处理和统计。
- 项目需要长期维护并托管在 GitHub。
- 软件采用分层架构，各层依赖方向必须清晰。

## 分层原则

需求确认后，建议至少评估以下逻辑边界。名称和是否独立成包由后续架构设计决定。

1. **表现层**：窗口、视图、交互状态和用户输入适配。
2. **应用层**：组织“打开、处理、统计、导出”等用例，不实现底层算法。
3. **领域层**：RAW 描述、像素数据、处理参数、统计结果及核心规则。
4. **基础设施层**：文件读取、格式解码、并行计算、缓存、日志和持久化。

依赖原则：

- 领域层不依赖 GUI、文件系统或具体图像库；
- 表现层通过应用用例发起操作，不直接解析 RAW 文件；
- 文件格式和算法实现可替换，并由稳定接口隔离；
- 大文件读取、缓存和任务取消被视为架构能力，而不是 UI 临时逻辑；
- 任何跨层例外都必须在 ADR 中说明原因。

## 架构设计前置输入

完成 [`../requirements/business-and-data-requirements.md`](../requirements/business-and-data-requirements.md) 后，架构设计至少输出：

- 系统上下文和主要用例；
- 分层、模块边界和依赖规则；
- RAW 数据内存模型与大文件策略；
- UI 技术、算法库、并发模型和发布方式的选型比较；
- 测试金字塔与基准样本策略；
- 安全、隐私、日志和故障恢复策略；
- 关键风险验证原型及 ADR。
